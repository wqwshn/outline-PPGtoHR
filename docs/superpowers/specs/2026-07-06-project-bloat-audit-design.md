# 项目臃肿审计脚本设计

## 背景

当前仓库包含历史过程文档、过期 worktree、实验输出和测试用大 JSON 等文件，已经影响本地磁盘占用与项目可维护性。需要先生成一份可复核的审计报告，由用户确认后再执行删除。

## 目标

- 在 `tools/audit-project-bloat.mjs` 中实现一个只读 Node.js 审计脚本。
- 默认从当前 Git 仓库根目录扫描，不删除、不移动、不修改被扫描文件。
- 输出 Markdown 报告，覆盖大文件、过期目录文件、以及已被 Git 跟踪但匹配 `.gitignore` 的生成文件。

## 扫描范围

脚本默认扫描仓库根目录，跳过明显不应递归审计的目录：

- `.git`
- `node_modules`
- Python 与测试缓存目录，如 `__pycache__`、`.pytest_cache`、`.ruff_cache`
- 本地环境目录，如 `.venv`、`venv`、`env`、`.conda`

`.worktrees` 不跳过，因为用户明确提到过期 worktree 文件是臃肿来源之一。

## 规则

1. 大型非代码文件
   - 阈值：大于 10 MB。
   - “代码文件”通过扩展名白名单排除，例如 `.py`、`.js`、`.ts`、`.m`、`.md`、`.json`、`.csv`、`.yaml` 等。
   - 注意：虽然 `.json` 和 `.csv` 属于结构化文本，脚本会在报告建议中单独提示大 JSON/CSV 可能是实验生成物。

2. 过期目录文件
   - 默认检查 `docs/archive` 和 `tmp`。
   - 阈值：超过 30 天未修改。
   - 若目录不存在，报告中记录为未发现。

3. Git 已跟踪但匹配忽略规则的文件
   - 通过 `git ls-files -ci --exclude-standard` 获取。
   - 结合文件大小标出大型候选，优先建议从 Git 跟踪中移除并保留本地，或迁移到归档目录。

## 输出

脚本默认在控制台输出 Markdown，并写入：

`reports/project-bloat-audit.md`

报告包含：

- 扫描时间、仓库根目录、阈值配置。
- 每类文件清单，包含路径、大小、最后修改时间和清理建议。
- 汇总统计：候选文件数量与估算可释放空间。
- 明确声明未执行删除。

## 使用方式

```powershell
node tools/audit-project-bloat.mjs
```

后续可按需增加参数，例如自定义阈值、过期目录或输出路径，但首版保持零依赖和默认可用。

## 风险控制

- 首版只读，不做删除。
- 绝对路径只用于内部解析，报告优先输出相对路径，便于人工复核。
- 删除动作必须在用户确认报告后另行执行。
