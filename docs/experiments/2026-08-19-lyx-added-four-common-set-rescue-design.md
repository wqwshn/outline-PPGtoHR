# LYX 新增四场景公共解救援设计

## 状态

本设计的场景原型阶段已经结束。Woli 的旧 profile 完成过 D0、D1 和 D2，但该 900-cell 精确计数不能外推到最终统一算法身份。Bobi、Tiaosheng、Woli、Xiezi 的原型现已收敛为同一个 `identity_blind_unified_rescue_v1`；最终 profile 在四个指定坐标上均得到三记录定向公共解下界 `>= 1`，尚未补齐任一场景的完整 300 点响应面。用户已确认下一步执行八场景 `24 × 300 = 7200` 完整响应面，本设计在交接经核验的响应面资格包处停止，不进入选择规则或科学身份讨论。Woli 历史原型见 `docs/reports/2026-08-19-lyx-woli-common-set-rescue-result.md`，统一算法阶段锚点见 `docs/reports/2026-08-20-lyx-identity-blind-unified-rescue-stage.md`，收敛执行方案见 `docs/experiments/2026-08-20-lyx-identity-blind-unified-physical4d-response-plan.md`。

## 目标与固定边界

- 对 Bobi、Tiaosheng、Woli、Xiezi 分场景恢复至少一个三记录共同准确坐标；不同场景可以使用不同固定坐标。
- 首阶段冻结现有 `3 × 5 × 5 × 4 = 300` 个 Physical4D 坐标，不扩轴、不加密网格。
- 主评价固定 `time_bias=5 s`，资格仅由 G1-I、G2、G3、G4、G5、G7 六门决定，不调整门限或用次级诊断挽救资格。
- 运行时规则必须跨场景通用，不读取场景、记录、坐标、参考心率、离线误差或评价门结果。
- 先逐场景完成原因诊断和一次只回答一个问题的快速原型，再执行完整响应面与跨场景防退化评估。

## 晋级顺序门

1. **D0：零 solver 因果重放。** 使用已冻结且哈希匹配的报告，只重放一个状态问题；不得把参考心率或评价结果作为运行时输入。
2. **D1：定向真实运行。** D0 支持假设后，在默认关闭的新算法身份下，对目标坐标的三条记录各运行两遍，共六次 solver。三份新报告必须逐对确定，且三条记录在冻结六门下全部通过。
3. **D2：目标场景完整面。** D1 通过后才运行目标场景 `3 × 300 = 900` 个 cell，独立复算三记录公共集；公共集非空才算场景救援成功。
4. **D3：完整八场景评估。** D2 通过后运行 `8 × 3 × 300 = 7200` 个 cell，按公共解保护等级逐场景报告。任何既有可达或已经救援的场景变空都阻止晋级。

全流程不运行 BO。只改善局部曲线、缩小门限缺口或在零 solver 重放中呈现预期状态，不等同于救援成功。

## 公共解保护等级

令修改前后的三记录共同准确集分别为 `C_old` 与 `C_new`：

| 等级 | 条件 | 解释 |
|---|---|---|
| S | `C_old ⊆ C_new` | 旧公共坐标全部保留；目标等级 |
| A | `C_old ⊄ C_new` 且 `|C_new| >= |C_old|` | 容量未减少，但集合发生迁移 |
| B | `0 < |C_new| < |C_old|` | 可达性仍保留，但公共集收缩；最低底线 |
| F | `|C_new| = 0` | 场景不可达；拒绝晋级 |

逐场景固定报告 `old/new/retained/lost/gained` 数量和集合重叠率。A、B 不能表述成“无退化”。

## 最终统一响应面资格包合同

2026-08-20 已确认当前对话的正式终点是 `identity_blind_unified_rescue_v1` 下八场景二十四记录的完整响应面资格包，而不是选择器执行结果。

### 冻结输入与重算边界

- 原样复用并现场重验 24 条 data/ref 及其哈希、300 点 Physical4D 坐标面板、历史独立 BO baseline、`time_bias=5 s` 对齐以及 G1-I、G2、G3、G4、G5、G7 六门合同。
- 新建统一算法实验身份、cache key、call manifest、source identity 和完成回执。
- 旧算法的 7200 个 solver report 只能作为对照，不能导入新响应面；新算法必须重新运行 `24 × 300 = 7200` 个 cell，BO 调用固定为 0。

### 硬性成功条件

- Bobi、Tiaosheng、Woli、Xiezi 各自精确 `|C_new| > 0`，否则新增四场景公共解问题仍未解决。
- Jianpan、Kaihe、Quanji、Run 也必须各自 `|C_new| > 0`；任何 F 级空集阻止资格包晋级。
- 既有四场景同时报告 S/A/B/F、`old/new/retained/lost/gained` 和重叠率。S 为目标，A/B 可以形成完整诊断包但不得写成无退化，F 不得交付为选择器可接收状态。

### 必备产物

1. 7200/7200 solver report、逐 cell 完成标志和 SHA-256；
2. 24 个各 300 行的原子记录分区，以及唯一 7200 行资格表；
3. 从原始报告独立重算全部 7200 个资格 cell 的物化回执；
4. 八场景精确公共集；新增四场景报告公共解数量、坐标、门限裕量与邻域；
5. 既有四场景公共集保护等级和集合差异；
6. 空集或脆弱单点场景的近失、失败门和裕量诊断；
7. 输入、合同、schema、evaluator、源码、profile、报告与产物哈希，以及 `successful_cell_count=7200`、精确 solver attempt 计数、`bo_invocation_count=0` 回执。

资格包完成并独立核验后必须硬停止，不生成 selector freeze、ranking、reveal、fold result 或 time-bias sensitivity 结果。

## Woli 冻结红点

首个救援场景为 Woli。最近三记录公共坐标为：

`physical4d:fs050:m160:mu0006:w018`

三份既有报告均已按 `cell_rows.csv` 中的 SHA-256 现场匹配：

| 记录 | 报告 SHA-256 | 六门结果 |
|---|---|---|
| `woli1_LYX_0708` | `1bc022908d8f0af971847309be5d7f6bd958f9ee1c52e793fc9b0bd85c39f309` | 仅 G2 失败，margin `-1` |
| `woli2_LYX_0708` | `0db5b55e5479610085cfbff0042af8e1a3b1fba4911816e748a249cc8a6db774` | 全部门通过 |
| `woli3_LYX_0708` | `235e8b0e1a233a74f02ad6bb13772b4e9a030e26c1f059229c51c344b6f22ff3` | G2/G3 失败，margin `-3/-1` |

使用正式 `+5 s` 参考对齐复算后：

- Woli1 唯一决定 G2 的 E10 episode 为算法时间 `94–104 s`，连续 `11 s`。低锁上方挑战在 `93/97/100/102 s` 分别建立，但中间窗口因 `near_penalty_harmonic` 重置，三窗确认无法连续完成。
- Woli2 的 L10/L20 为 `9/5 s`，六门全部通过，是同坐标首要非回归哨兵。
- Woli3 的 E10 episode 为 `120–132 s`，连续 `13 s`；E20 episode 为 `126–128 s`，连续 `3 s`。约 `79–81 BPM` 的下方候选持续可见，但受固定 `85 BPM` 高锁候选下限、惩罚排除与确认连续性共同阻断；运动后直到 `133 s` 才下切。

因此，“只修运动后交接”不能完整救援 Woli：Woli3 的 G3 红段全部发生在运动段，Woli1 红段也发生在运动段。两条独立 baseline 在这些记录上均通过，输入、参考和评价器不是当前首要根因。

## Woli 可证伪假设与原型

### P0-A：低锁挑战支持连续性

问题：一个已经由现有合法入口取得的低锁上跳目标，随后短暂进入惩罚排除带时，若同一候选仍在未惩罚频谱中、仍处于既有 `10 BPM` 稳定带，是否应只作为该目标的支持证据继续计数？

原型只改变状态重放，不把惩罚带候选放回主选择器、不强制选峰、不写 Final。若目标无法在 Woli1 `100–102 s` 形成满足既有双证据规则的连续链，或在安全哨兵产生额外确认，本假设被证伪。

### P0-B：高锁恢复入口切断点

问题：Woli3 的恢复究竟被现有预声明高锁候选中的固定 floor、相对 gap、惩罚排除还是确认期限切断？

先对既有候选身份做零 solver 重放，不新增阈值。若现有候选均不能在 `126–128 s` 前形成合法恢复链，则停止把“调一个现有高锁参数”当作解释，另行设计只读取在线证据的新候选；不得直接放宽 raw 低频切换。历史 Kaihe 证据已经证明 raw/FFT 低频一致也可能是共同错误低锁。

### 组合与停止规则

- P0-A 与 P0-B 分开回答、分开记录；只有各自的因果预测成立后，才允许组合成一个包含低锁和高锁两个方向的通用、默认关闭候选。
- 组合候选必须保持单一 Final writer、状态所有权闭合、EOF/运动结束终止，并继续禁止任何场景或记录身份输入。
- 六次定向 solver 未使三条记录全部通过时，立即停止在该候选上扩算 900-cell。
- 900-cell 公共集为空时，不运行 7200-cell；返回本设计重新裁决下一条 Woli 假设。
