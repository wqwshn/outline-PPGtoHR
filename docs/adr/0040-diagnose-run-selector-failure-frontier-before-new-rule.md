# 在新增选择规则前诊断 Run 失败前沿

Status: accepted

四条预注册训练侧选择原则的纯表格证据原型已完成并经独立复算：十二个留一折的三记录共同准确集均非空，但没有规则满足跨四场景统一晋级门，正式裁决为 `NO_SELECTOR_CRITERION_IDENTIFIED`。表现最好的 `historical_platform_control` 在 Jianpan、Kaihe、Quanji 均为 `3/3`，只在 Run1 与 Run3 留出折失败；Quanji 在四条规则下均为 `3/3`。因此当前问题定义为训练侧排序辨识失败，而不是参数空间不可达、BO 漏搜或 Quanji/rise 风险阻碍选择。

下一独立任务先执行 Run 失败前沿可辨识性诊断，不直接发明第五条规则，也不启动 BO。冻结 Run1 与 Run3 两个失败折中四条既有规则的 top-3 候选并集，共二十二个物理坐标、六十六个 cell。既有矩阵的六十六个 cell 均已真实执行 rise-on solver，性能、Final 和评价门来自该次运行；其中只有九个 cell 持久化了 direct rise-on report，其余五十七个只有不主张机制等价的 control trace surrogate。任务先有界重跑并持久化这五十七份 direct report，以补齐时序与机制可观测证据，而不是修复性能响应面的算法身份；不得自动扩大到其余 2333 个 surrogate cell 或重跑 3600。

Run 诊断与选择器优化必须分成两个独立任务。诊断任务只允许闭合 direct 证据、解释既有失败并返回候选信号，不得在看到诊断结果后实现、调试或筛选第五条规则。只有诊断证据返回主对话并重新冻结候选特征、规则数和验收合同后，才可另行派发最多一至两条统一规则的开发任务。

诊断分为两个顺序门。第一门逐点比较补齐后的 Final、评价指标、失败门、训练特征、确认决策与既有前沿身份；若候选标签、排序或失败结构发生实质变化，返回 `FRONTIER_IDENTITY_CHANGED`，保留旧 prototype 的历史负向结论并停止，不假设其余坐标不受影响。只有前沿身份稳定时才进入第二门：分别审阅 Run1 的 G5 尾端未恢复和 Run3 的 G2/G3 长误差，并比较前沿失败坐标与最近安全坐标在两条训练记录中的时序误差、既有运行时可观测求解证据和机制交互。

新增 solver 运行严格限制为上述五十七个 cell；任务可以只读分析 Run 全部三百坐标的既有性能响应面，但不得因诊断困难自行补跑其他 direct trace、2333 个 surrogate 或完整矩阵。冻结范围内仍无法回答时，应以范围内证据不足返回主对话，由后续决策重新授权，而不是把任务范围滚动扩大。

曲线统一沿用项目“批量全流程”可视化风格；展示 HF 自适应滤波结果时同步绘制 ACC。留出记录曲线、HR_ref 和揭盲标签只用于解释失败与给开发证据打标签，不得成为运行时选择器输入，也不得用于事后调阈值。top-3 并集在十二折均含安全坐标只是揭盲后的诊断事实，不能升级为 top-k、投票或 oracle 选择器。

诊断只预注册三个有限证据族。E1“轨迹与频谱一致性”描述 Final 与 FFT/候选峰的偏离、候选支持与排名以及连续缺失或不采纳时长；E2“状态持续与恢复能力”描述 reacquire、high-lock、rise、penalty 和 protection 等运行时状态的持续、触发、超时与运动后闭合；E3“双训练记录一致性与稳健性”只对 E1/E2 取两记录最坏值、差异和冻结单轴邻域稳定性。三族只做成对方向与机制解释，不开放任意字段组合、学习权重或搜索阈值。`mechanism_target_ownership` 及同类审计账本只用于验证生命周期和证据完整性，明确排除于未来选择器特征；solver 自然产生的状态、触发与恢复时长仍可作为 E1/E2 候选观测。

五十七个待持久化 cell 必须完整执行两遍，共一百一十四次 solver 调用。第一遍生成 direct report，第二遍作逐点确定性复算；两遍必须在 Final 轨迹与哈希、指标、评价门与连续裕量、确认决策序列和规范化语义哈希上完全一致，并分别与冻结矩阵的性能身份一致。任一不一致直接返回 `DIAGNOSTIC_INVALID` 或在冻结身份变化时返回 `FRONTIER_IDENTITY_CHANGED`，不得采用多数票。已有九份 direct report只读复用并由独立验证器重算，不计入新增 solver 调用。

当前 LYX 每场景三条记录已经全部归入选择器开发与机制诊断数据。依据 Run1/Run3 揭盲结果形成的新特征或规则，即使在旧十二折回代达到 `12/12`，也只能称为开发判据候选与读取隔离通过，不能称为独立泛化确认。当前阶段按用户裁决先不新增数据样本；这一安排不改变最终同个体跨穿戴泛化仍需冻结后未参与开发记录的证据要求。

诊断只允许四种全局结果：`TRAIN_ONLY_SIGNAL_CANDIDATE_IDENTIFIED`、`NO_TRAIN_ONLY_SIGNAL_IDENTIFIED`、`FRONTIER_IDENTITY_CHANGED` 或 `DIAGNOSTIC_INVALID`。其中 `TRAIN_ONLY_SIGNAL_CANDIDATE_IDENTIFIED` 必须同时满足：信号可在留出揭盲前从两条训练记录或运行时 solver 证据计算；以同一方向解释 Run1 与 Run3；不是对 `fs`、memory、`mu`、width 或具体坐标的黑名单；不读取场景名称、HR_ref 或留出指标；并且在 Jianpan、Kaihe、Quanji 的既有前沿候选上没有明确误杀反证。只解释单个失败折的发现标为 `FOLD_SPECIFIC_CLUE`，不得晋级为通用规则候选。

若识别出满足门槛、在训练记录可观察且具机制解释的候选信号，后续可另立有界选择器优化任务，最多预注册一至两条可解释规则，不学习权重、不开放特征搜索、不进入 BO；旧十二折只作开发回代。新规则必须使用同一组候选资格、训练侧特征、排序键和并列规则机械应用于四场景，不得读取场景名称设置 Run 专用分支、阈值或权重；Run 只用于发现通用风险证据。任何优化候选都必须重新复算 Jianpan、Kaihe、Run、Quanji 全部十二个留一折，并以 `12/12` 通过完整 `engineering_pass_v2` 作为开发晋级门，不能只修复 Run1/Run3 或默认其余十折不退化。若未识别出统一信号，先完整记录 Run 失败原因与选择器限制，再回主对话裁决是否继续规则工程；本 ADR 不把新增记录设为当前诊断的前置条件。
