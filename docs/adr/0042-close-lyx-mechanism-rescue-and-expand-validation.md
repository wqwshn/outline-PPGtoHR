# 收口 LYX 机制救援并转入扩大验证

Status: accepted

LYX 四场景开发数据已完成物理四维响应面、共享参数选择器、Run 失败因果归因和非破坏性运动惩罚研究。`suppressed_protected_continuous_visibility_v1` 在冻结 LYX 因果与非回归面板上得到 `SUPPRESSED_PROTECTED_CONTINUOUS_VISIBILITY_BOUNDED_PASS`，使固定历史平台规则的开发回代由 `10/12` 提升到 `11/12`；剩余失败仅为 `run1_LYX_0708` 的 G5 尾端恢复问题。由于这些记录已经反复揭盲，继续针对同一失败优化会增加过拟合和机制复杂度，且边际收益不足，因此结束本轮 LYX 机制救援。

连续可见性机制保留为默认关闭的有界开发候选，不升级为生产默认，也不据此宣称同场景跨穿戴或跨个体泛化完成。Run1 G5 登记为已知开发缺陷；只有新穿戴或新个体数据以同一表型重复出现并实质影响扩大验证，才重开该机制问题。上升候选谱系仍按既有裁决默认关闭，Quanji 假阳性风险不因本轮 Run3 修补而解除。

下一主线转入更广泛场景、新穿戴和跨个体数据：先冻结待验证算法身份、候选启用策略、物理四维空间和评价合同，再用未参与当前机制设计的记录验证共享参数可迁移性。BO 只在明确需要降低训练期完整网格成本、且已有可验证的选择准则后进入；它不能替代选择规则证据，也不在测试记录上运行。旧 3600 行响应面继续作为旧算法开发证据，不能充当连续可见性候选的新响应面。

后续若重新开启机制研究，必须继续遵守参数—机制责任分界门：先证明失败无法由训练侧冻结资格可靠规避，再证明同一既有机制 seam 在多个部署可达坐标上产生可重复伤害；修补优先保持单一职责、无场景/记录/HR_ref 标签、无新增 Final writer，并用有界四场景非回归后再扩大计算。
