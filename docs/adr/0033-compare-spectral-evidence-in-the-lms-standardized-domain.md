# 在 LMS 标准化域比较滤波前后频谱证据

Status: accepted

## Context

LYX p25 诊断在三个滤波档位、12 条记录上得到 0/36 的
`pulse_power_retention` 通过数，而其余相对频谱子门并未同步全部失效。
随后批准执行的 proposal
`429233ecadf92cc2d669b59c8f2cc4516b3d767547d98919655a18918e1a60bd`
在写字、敲键盘、跑步和开合跳各三条记录上比较了三个确定性通道：

- 原始信号直接旁路；
- 原始幅值域 `before` 与零更新 LMS 输出的旧量纲比较；
- `before` 与零更新 LMS 输出都位于样本 z-score 域的同量纲比较。

直接旁路和同量纲零更新通道均为 12/12 通过，脉搏功率保留率都为
1.0；旧量纲通道的保留率只有
0.000294–0.002459，中位数为 0.000745，且在 12/12 条记录上复现失配。
这排除了“零更新本身削弱脉搏能量”和“异常只由某一运动强度场景驱动”
两种解释。

根因位于公共频谱评估入口。`lms_filter` 会把参考信号和期望信号分别转换为
样本 z-score（`ddof=1`），并在该表示中返回残差；旧评估器却把该残差与原始
幅值域的滤波前 PPG 计算功率比。该比值因此混入原始窗口方差的尺度因子，不能
只解释为脉搏成分的相对保留。

## Decision

- `evaluate_stage_r_spectral_gate_windows` 在计算全部五项相对频谱证据前，
  使用 `ppg_hr.core.lms_filter.standardize_lms_signal` 分别把每个窗口的
  `before` 和 `after` 转换为样本 z-score 域。
- `StageRSpectralGateContract` 升级为
  `lyx_stage_r_spectral_gate_v2`，并在合同中显式冻结：
  `before` 和 `after` 都采用
  `sample_zscore_ddof_1_per_window`。
- 五项门槛数值保持不变。此次修订只修正指标输入量纲，不放宽
  `pulse_power_retention >= 0.80` 或其他频谱安全要求。
- Stage R 与 Stage F 的新提案均发布 v2 频谱合同；v1 产物保留为历史诊断证据，
  不允许原地重分类为 v2 结果。
- 修改评估语义后必须为 p25 档位发布新的精确身份提案并重新计算。源码哈希、
  评估哈希和频谱合同哈希变化意味着旧 36 个身份不得充当新合同的缓存命中。
- 此修订不授权参数搜索、独立 BO、Stage R 或 Stage F 自动执行。

v2 频谱合同 SHA-256 为
`8df3e7f1d6c2b933a2b6996c9966ea0ceb0b10a1f7ac8ce23b0c337aa3b97d28`。

## Considered options

- 只在 `audit_stage_r_profile_record` 调用点标准化 `before`：拒绝。其他调用者仍可
  把不同量纲数组传入公共评估器，合同无法在真正的语义边界上封闭。
- 把 LMS 输出反变换回原始幅值域：拒绝。级联 LMS 每一级都会重新标准化当前
  期望信号，现有输出不携带完整的逐级反变换状态；补造反变换会改变求解器接口，
  超出本次指标修复范围。
- 保留 v1 合同版本、只依靠源码哈希区分：拒绝。相同合同哈希对应不同输入量纲
  会破坏提案审计和跨阶段复用语义。
- 删除脉搏功率保留门：拒绝。量纲错误不等于该安全门没有价值；修正后仍需检验
  滤波是否改变心率邻域在标准化窗口内的相对功率。

## Consequences

- v2 的 `pulse_power_retention` 衡量标准化窗口内真实心率邻域的相对频谱功率，
  不再衡量原始物理幅值是否被保留。这与当前 LMS 输出及下游心率估计所消费的
  表示一致。
- 如果后续需要约束原始物理幅值，应新增独立的原始域指标和可逆尺度状态，而
  不能复用 v2 的脉搏功率保留率。
- 旧 p25 失败结论只能说明 v1 评估口径失效；三个档位在 v2 下是否安全仍需新的
  36 坐标复验。
- 当前证据仍是 `development_reuse_pilot`，只支持 LYX 个体内机制修正，不支持
  未见场景、跨个体或算法级留出泛化结论。
