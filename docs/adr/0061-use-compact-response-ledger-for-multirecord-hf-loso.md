# 多记录 HF LOSO 使用紧凑响应账本

143 条面板记录与冻结的 300 个 Physical4D 坐标形成 `143×300=42,900` 个 HF 响应单元。正式计算采用 SQLite 紧凑响应账本作为运行事实源，并导出排序稳定的 canonical CSV 供审计与选择；不为全部单元永久保留完整求解报告。实验产物只归档在本地 `data/experiments/`，不进入 Git 历史或远端仓库。

响应单元的唯一调用身份由 `experiment_id`、真实 `physical_subject_id`、`scene`、`record_id`、`route_id=HF`、`coordinate_id`、算法身份、输入哈希和评价合同共同约束。原始响应单元不写入 fold，因为同一记录在当前设计中只对应其场景内唯一的留出折，折选择与揭盲身份另由不可变 selection receipt 记录。完全相同的调用身份允许幂等命中；相同主键但算法、输入、坐标或合同身份冲突时必须失败，不得覆盖旧值。

每个有效响应单元至少保存选择和报告所需的固定五秒标量：候选 MAE、历史 Lite HF 基线 MAE、G1-I 状态、L10、L20、相对基线误差差值、最终窗口 E10 右删失状态、G7 对应值、六门逐项状态与裕量、共同有效窗口身份，以及来源、算法、参数、输入、基线和评价合同哈希。只保存 MAE 不足以重建六门资格或选择证据。技术超时、进程异常、输入不可读和输出缺失写入独立 attempt event，不得伪装为惩罚 MAE 或有效门失败。

运行进程使用单一写入者或等价的串行提交边界批量落盘；完成状态以账本提交为准，不以工作进程退出码、日志行或临时目录存在为准。续跑先按完整调用身份查询，精确命中才跳过；导出必须采用固定字段顺序、固定记录与坐标排序和确定性数值格式。账本元数据固定实验身份、143 条数据清单哈希、300 坐标顺序哈希、算法身份、固定 5 秒评价合同、基线清单哈希和软件版本。

四十八折训练选择仅消费训练分区的 canonical 响应，输出所选坐标、完整字典序键、训练受试者聚合值、并列裁决、输入哈希和代码身份。所有选择回执封存后才允许报告器读取留出分区。报告器只物化记录、折、场景和总体统计，不重新调用求解器，也不改变选择。

完整求解报告仅为最终 143 个获选记录—坐标单元及技术失败、门边界或审计抽查等风险单元定向重放。定向重放必须使用原调用身份并核对紧凑标量一致性；不一致时记录身份冲突并停止结果物化。未来 ACC 运行仍写为实际 `route_id=ACC`，其坐标来源在独立回执中声明为冻结 HF 选择，不能将 ACC 结果写成 HF 或在本阶段生成 42,900 个 ACC 单元。
