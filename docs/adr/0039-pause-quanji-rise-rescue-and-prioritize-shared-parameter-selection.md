# 暂停 Quanji 上升谱系救援并优先研究共享参数选择

Status: accepted

有界上升候选谱系使 Kaihe 重新出现共享参数可行坐标，但在 Quanji 六个既有安全坐标发生假阳性确认；有限判据辨识又显示当前正负事件在现有运行时证据上不可稳定分离。完成所有权与证据合同修复后的快速正式复算若仍得到 `NO_SEPARABLE_CONFIRMATION_CRITERION`，本轮即停止新增确认门、阈值和特征组合，将该机制登记为默认关闭的已知风险候选；不再要求消除全部坏坐标后才研究参数选择。

下一研究主线转为同场景跨记录共享参数：先检验只读取训练记录的选择器能否选出使各留出记录心率通过完整评价合同的参数，再决定是否需要正式 BO。三折是否选择相同坐标、相邻坐标或稳定参数平台只作行为诊断，不作为主通过条件。Quanji 局部退化只有在训练侧无法识别风险、留出折持续失败，或 Kaihe 可行区与 Quanji 风险区不可选择地冲突时才重新打开机制救援。现有开发记录上的三折只作为选择器读取隔离与可选择性审计；正式泛化结论仍要求选择器冻结后的未参与开发记录。

正式选择器实现前先运行纯表格证据原型：以 `physical4d_corrected_development_gates_v2` 的 `engineering_pass_v2` 定义训练共同准确集和三记录共同准确集，比较跨场景统一、有限且可解释的训练侧选择原则。`strong_match_v2`、参数平台和坐标一致性只作次级分析；原型不得运行 BO、重算 solver、按场景定制规则或把开发留出结果冒充独立泛化证据。

Quanji 快速收尾后，选择器证据原型只研究开启 rise 的四场景候选算法身份，并显式携带其默认关闭与 Quanji 假阳性风险标记。rise 关闭身份对 Kaihe 可达性的影响已经由既有机制实验和完整矩阵回答，不在本轮重复设置对照臂；只有后续三折失败证据显示 rise 风险构成共享参数选择的实际阻碍时，才另行重开机制对照或救援。

证据原型只比较四条预注册确定性原则，不学习权重、不搜索阈值、不得事后改变排序键：

1. `minimax_mae`：最小化两条训练记录中的最坏 MAE，并列时按冻结物理坐标顺序。
2. `maximin_gate_margin`：G1-I 与 G5 只作布尔资格过滤；G2、G3、G4、G7 以及适用场景的 G6，分别在本 fold 的训练共同准确集内把每条训练记录的连续安全裕量转成越大越好的百分位，最大化所有适用“记录 × 门”中的最弱百分位，并列时按冻结物理坐标顺序。
3. `agreement_then_minimax`：将两条训练记录的 MAE、L10、L20、E10 占比和 E20 占比之差，分别在本 fold 候选池内转换为越小越好的百分位；先最小化五项中的最差差异百分位，再最小化最坏训练 MAE，最后按冻结物理坐标顺序。
4. `historical_platform_control`：沿用下述冻结历史近优平台规则。

E10/E20 占比的分母是对应记录在冻结评价重叠区内的有效窗口数，必须由输入身份清单冻结，不得用不同记录的原始计数直接比较。每次按场景留一时，规则必须先在其余三个场景全部达到三折留出预测通过；多个合格规则按上述简单性顺序冻结，再应用到隐藏场景。全四场景开发结果若有多条规则同时通过，也按同一顺序只冻结一条进入下一阶段。

历史近优平台对照沿用一条固定、可复算的旧规则，而不重新调参：先在训练共同准确集中保留最坏训练 MAE 不超过本 fold 最优值 `0.5 BPM` 的近优池；邻居只定义为当前四维物理网格中单轴相邻一个档位的坐标；支持邻居必须在两条训练记录均通过 `engineering_pass_v2`，且其最坏训练 MAE 不超过中心坐标 `1 BPM`。候选依次按支持邻居比例、支持邻居数、悬崖数、训练平均 MAE 和冻结物理坐标顺序排序。该规则始终只作历史对照，不能因为单独一次三折成功而自动成为默认规则。

prototype 晋级要求 rise-on 身份的十二个 fold 均存在三记录共同准确坐标、同一候选规则在四场景各自 `3/3` 通过 `engineering_pass_v2`，且四次按场景留一均在隐藏场景 `3/3` 通过。`strong_match_v2`、参数距离和平台指标只作次级报告；没有规则通过时返回 `NO_SELECTOR_CRITERION_IDENTIFIED`，不得自动增加特征、调整权重或启动 BO。

Quanji 收尾与选择器 prototype 分为两个任务。收尾任务仅允许闭合已知所有权目标对应关系与历史测试回执，完成一次测试、192 份 direct report 重跑、独立验证和双轨审查；若三条确认规则仍失败同一红例，即正式记录 `NO_SEPARABLE_CONFIRMATION_CRITERION` 并停止。禁止新增确认规则、阈值研究、72-cell、TS 和 3600；一次修复复核后若仍需扩大设计范围，必须返回主对话。只有数值算法身份未改变时，后续 prototype 才可复用既有 rise-on 3600 行响应面。

旧 rise-on 3600 行响应面的复用必须满足更严格的身份门：192 份正式重跑逐点证明 Final、指标、评价门和确认决策序列与旧结果完全一致，且 Standards/Spec 双轨审查确认本次修改仅修复证据与生命周期表达、不改变数值决策路径。prototype 必须绑定旧矩阵的冻结源码身份，并将结果称为“已有风险候选响应面分析”，不得声称它是当前修改后源码的新矩阵。任一数值或确认决策发生变化即停止复用；不得自动重跑 3600，必须返回主对话重新裁决。

prototype 的正式证据包至少包括：输入响应面、评价合同和源码身份哈希清单；十二个 fold 的可达性与集合统计；四条规则逐 fold 的完整排名和 top-1 回执；四次按场景留一的规则冻结与隐藏场景结果；只含训练侧可见量并另列揭盲标签的逐候选特征表；机器可读汇总；以及从源 3600 行响应面独立重算集合、排名、top-1、指标与评价门的验证回执。单文件交互式 HTML 只嵌入上述冻结数据用于审阅，不是唯一证据，也不生成新的心率曲线。

既有矩阵的 3600 行性能、评价门与物理坐标字段可以完整用于上述排序和留出揭盲；四条规则不得读取 rise trace、机制所有权或其代理字段。机制解释仍受原证据边界约束：只有 1267 个 cell 具有 direct mechanism-on trace，其余 2333 个 control surrogate 不主张机制等价。prototype 可以对全部 3600 行作性能响应面分析，但若结果需要归因到 rise 的触发、拒绝、所有权或 Final-writer 行为，只能引用 direct 子集并明确样本范围。

全局裁决只有三种：`SELECTOR_CRITERION_IDENTIFIED` 表示所有预注册晋级门通过；`NO_SELECTOR_CRITERION_IDENTIFIED` 表示证据有效但四条固定规则均未通过；`PROTOTYPE_INVALID` 表示身份、输入完整性、读取隔离、确定性或独立重算失败。局部失败必须分别报告 `UNREACHABLE_FOLD`、`SELECTION_MISS` 与 `SCENE_HOLDOUT_RULE_FAILURE`，不得用跨场景平均结果覆盖。

十二个 fold 共享场景和记录，不能当作十二个相互独立的统计重复。报告必须保留四场景各三折的逐格结果、逐 fold 三记录共同准确集命中率及失败归因，不计算或宣称“12/12 即 100% 泛化率”，也不以合并均值覆盖任一场景失败。原型只能辨识开发数据中值得正式实现的选择原则。

若原型得到 `SELECTOR_CRITERION_IDENTIFIED`，下一阶段先将命中的唯一冻结规则实现为完整响应面离线三折执行器：仍使用全部 300 个坐标，独立复算候选资格、排名、top-1 和留出评价，不立即引入 BO。正式执行器通过后，才允许另开有限预算搜索实验，以完整响应面的冻结选择结果为参照，评估较小候选预算能否保持各折留出准确性。BO 只减少开发期训练记录的选参成本；未来新穿戴记录直接使用冻结的场景共享参数，不运行 BO。若原型返回 `NO_SELECTOR_CRITERION_IDENTIFIED`，不得通过 BO、扩大特征族或调权重绕过该负向裁决，必须回到主对话重新规划。

完整响应面离线三折通过后，才允许执行“三折后全三条开发拟合”。每个场景的最终候选域固定为三条开发记录的共同准确集，所选规则从两记录机械推广到三记录：`minimax_mae` 取三记录最坏 MAE；`maximin_gate_margin` 取所有适用“记录 × 连续门”的最弱百分位；`agreement_then_minimax` 先取三对记录之间五项指标差异的最差百分位，再取三记录最坏 MAE；历史平台对照则要求支持邻居在三条记录均通过评价门，并使用三记录最坏 MAE。所有并列仍按冻结物理坐标顺序。该最终场景档位只用于后续新穿戴记录的固定参数验证；全三条拟合本身不增加泛化证据。
