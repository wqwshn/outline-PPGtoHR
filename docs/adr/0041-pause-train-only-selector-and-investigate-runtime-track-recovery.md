# 暂停训练侧选择规则工程并研究统一运行时错误轨迹恢复

Status: superseded by ADR-0042

本 ADR 保留从选择器失败诊断到 Run3 运动惩罚机制研究的完整决策链。LYX 机制救援的最终状态、保留风险和后续研究方向由 ADR-0042 接续。

Run 失败前沿诊断已补齐五十七份 direct report，并对五十七个 cell 完成两遍确定性复算。冻结的六十六个前沿 cell 与既有 3600 行响应面在 Final、指标和评价门上逐点一致，独立验证通过。Run1 的主要失败是错误轨迹延续到记录尾端且在 EOF 前没有形成足够恢复窗口，触发 G5；Run3 的主要失败是记录中段错误轨迹持续过久，触发 G2/G3，部分坐标同时触发 G4/G7。预注册的 E1、E2、E3 训练侧证据没有形成一个能以同一方向覆盖 Run1 与 Run3 安全/失败对的信号，正式裁决为 `NO_TRAIN_ONLY_SIGNAL_IDENTIFIED`。

该负向结果不改变物理空间可达性：十二个留一折均存在三记录共同准确坐标；当前最好训练侧规则在 Jianpan、Kaihe、Quanji 各为 `3/3`，在 Run 为 `1/3`。它也不表明 BO 漏搜或 Quanji/rise 风险阻碍选择。继续在已经揭盲的同一批 LYX 记录上增加第五条规则、搜索权重或调阈值，只会扩大事后拟合空间，因此暂停当前训练侧选择规则工程，仍不得进入 BO。

下一阶段把优化对象从“用两条训练记录预测哪个坐标在第三条记录安全”切换为“冻结算法在新记录运行时能否识别并恢复缺乏可信支持的错误轨迹”。这不是 Run 专用修复：任何候选观测、触发、状态处置和恢复动作必须使用同一公式机械应用于 Jianpan、Kaihe、Run、Quanji，不读取场景名称、记录身份、HR_ref、留出误差或评价门标签。Run1 与 Run3 只提供两种已知失败表型；不得分别按 G5 与 G2/G3 写两个补丁。

机制研究采用“既有机制修补优先”。诊断必须先把首次错误选择、机制触发/抑制、内部动作、下游平滑/限速和 Final writer 串成因果链，并将问题归入现有职责：运动段优先审计谱峰惩罚与历史保护、高锁逃逸、低锁重捕获和 rise 谱系的顺序与目标可见性；运动后优先审计 PM-CHR 的启动、目标可消费、不可逆交接和单一 Final writer。若现有机制已经识别目标但动作被下游 writer 抵消，或错误目标已经由现有机制取得所有权，则修补该接口/合同，不新增并行恢复器。只有证明所有现有职责均不覆盖时，才允许由主对话裁决是否引入新机制。

因果归因与机制修补必须分成两个独立任务。第一任务可以运行冻结消融 lane、增加 throwaway 观测和形成职责/交互裁决，但不得修改生产算法、改变默认配置、实现候选修复或在观察消融结果后追加新 lane。它必须先返回 `EXISTING_MECHANISM_CONTRACT_GAP`、`MECHANISM_INTERACTION_CONFLICT`、`NEW_MECHANISM_GAP` 或 `DIAGNOSTIC_INVALID`，由主对话冻结后续最小修补范围；不得用多个同时变化的补丁互相补偿后直接报告性能改善。

首轮归因面板冻结为既有 `failure_safe_pairs.csv` 的六组失败—安全配对，共十一个不重复 cell：Run1 四个 G5 失败坐标与三个不重复安全坐标，Run3 两个 G2/G3 失败坐标与两个安全坐标。不得自动扩到完整六十六个 selector 前沿 cell。已有 rise-on direct report作为基线复用；新增反事实 lane 每个执行两遍并要求语义完全一致，solver 新调用硬上限为八十，BO、其他记录、3600 矩阵和生产写入均为零。

Run1 的冻结问题是 PM-CHR 首次正式交接与交接后目标身份延续的必要因果：诊断比较完整基线、PM-CHR 仅保留 shadow 计算而不消费 Final，以及阻断交接后目标漂移的 counterfactual。Run3 的冻结问题是运动惩罚/历史保护、rise、高锁逃逸与下游 Final 动态的必要因果及交互：诊断只比较完整基线、rise-off、high-lock-off、rise-off×high-lock-off、惩罚候选不移除、历史保护关闭以及高锁事件后绕过下游降速的 shadow 输出。上述 lane 均为 throwaway 因果干预，不是候选修复，不得因某一 lane 改善而写入生产默认。

研究按两个顺序门执行。第一门是统一运行时证据诊断，只比较冻结失败/安全对和跨场景反例中，部署时可获得的谱峰支持、跟踪采纳、惩罚与保护、锁定/重捕获生命周期、下游 writer 和恢复时序。只有存在一个具有机制解释、在 Run1 与 Run3 同向、且没有被其他已通过样本直接反证的候选信号，才允许进入第二门。第二门最多实现一个 throwaway 机制家族，先采用最小状态和最小 Final 权限，不修改冻结评价合同、物理四维空间或参数选择规则。

候选机制的开发验收必须重新覆盖四场景十二个留一折，不能只复算 Run。Run1 与 Run3 必须通过完整 `engineering_pass_v2`；其余十折不得丢失既有通过结果；任何新增失败门、场景/记录分支、HR_ref 依赖、无法闭合的所有权或 Final-writer 证据都阻止晋级。旧十二折已经全部属于开发揭盲数据，即使回代达到 `12/12`，也只能称为开发机制候选，不能称为独立跨穿戴泛化确认。

本阶段不启动 BO、不新增数据、不重开 Quanji 上升谱系确认研究，也不自动整批重跑 3600。若第一门没有统一运行时信号，返回 `NO_UNIFIED_RECOVERY_SIGNAL_IDENTIFIED` 并停止机制设计；若证据或算法身份无效，返回 `EXPERIMENT_INVALID`。只有得到 `UNIFIED_RECOVERY_SIGNAL_CANDIDATE_IDENTIFIED`，才由主对话另行冻结最小 prototype 的接口、范围、非回归面板和计算预算。

首轮十一 cell 因果任务最终裁决为 `DIAGNOSTIC_INVALID`：首次长路径证据根在路径错误终止前至少完成了一次未注册科学 lane，随后短路径根又完整执行预注册七十六次，违反调用合同。短路径七十六份报告的输入身份、两遍确定性、raw report、指标和评价门均可复算，只能作为哈希冻结的探索性输入；不得通过重写回执或原样重跑七十六次追溯性转正，也不得授权生产修补。

探索性证据将后续顺序收敛为“Run3 先于 Run1”。Run3 的 penalty 候选删除发生在两个失败 cell 的长错误 episode 和 high-lock 触发之前；取消删除可在冻结面板救援两个失败 cell且不破坏两个安全 cell的评价门。high-lock-off 明显恶化，说明 high-lock 是保护机制；既有离线 shadow 又提示其内部恢复被下游 Final 动态减慢，但没有传播后续在线状态。Run1 的 PM-CHR 输入来自运动段终态，Run3 的运动段修补可能改变该输入，因此在 Run3 正式隔离与最小修补裁决返回前暂停 Run1 新计算。

下一正式任务只冻结 Run3 的两个失败和两个安全 cell。旧 rise-on baseline只读复用；执行三个新 lane并各重复两遍：一是带逐窗 would-remove provenance 的候选删除反事实，二是 high-lock 内部结果通过既有 Final seam 在线提交且后续状态继续传播，三是二者联合以区分上游主效应、下游抵消和交互。计划与硬上限均为二十四次 solver；不得使用余量追加 smoke 或科学 lane。任务只做因果归因，不修改生产算法；结果返回主对话后再决定是否以及先修补哪个既有 seam。

上述二十四次 Run3 隔离任务已经执行，但正式裁决为 `DIAGNOSTIC_INVALID`：执行器在内存中评价完整 report，落盘时却保存了字段层级不同的缩减 envelope，独立 validator 重新载入后把二十四份报告的 G1-I 全部从 PASS 重算为 FAIL。该根只能保留探索性信号，不能授权生产修改。下一步必须先以零 solver 的 TDD 任务冻结唯一 evaluator 输入投影，证明内存评价与落盘重载评价逐指标、逐门和逐 margin 完全一致；同时把 high-lock 比较限制为预注册的 high-lock 专属字段。只有该基础设施任务 PASS，才允许新建科学证据根。

完整四维响应面进一步证明 Run3 的问题不是所有参数共有：Run3 单记录有一百二十九个坐标通过，Run 三记录有六十一个共同通过坐标；Run1 与 Run2 共同通过的一百五十六个坐标中，仍有九十五个在隐藏 Run3 上失败。两个 selector 失败坐标只把 `mu=0.008` 改为 `0.006` 就得到三记录共同通过的相邻坐标，而训练两记录的 MAE 反而轻微偏好失败坐标。因此本阶段采用“参数—机制责任分界门”，不得把问题简化为纯选参失败，也不得因两个红点的探索性救援称为全局生产机制漏洞。

证据管线修复通过后的正式复核扩为两个冻结参数层级各四个 cell：`fs25/mu0.008` 的 Run3 安全端点、`fs50/mu0.008` 的训练合格但 Run3 失败中间点、`fs100/mu0.008` 的 selector 失败点，以及 `fs100/mu0.006` 的三记录共同安全邻点；两个层级分别固定 `m40/w3` 与 `m120/w6`。八个 cell 只运行候选删除反事实 lane并各重复两遍，共十六次 solver，BO、其他记录、生产写入和观察后扩跑均为零。

若四个 `fs50/fs100` 失败点均在首次 `would-remove` 后形成同一因果链并被反事实救回，同时四个安全点不新增失败门，则返回 `PARAMETER_CONDITIONED_EXISTING_MECHANISM_GAP`，只授权另立最小生产 TDD 修补与四场景非回归任务；不得直接关闭运动惩罚或修改默认。若只在原始红点等狭窄坐标生效，则返回 `NARROW_COORDINATE_INTERACTION` 并停止生产机制修改，回到参数资格或新增数据路线。若安全点退化，则返回 `NO_GENERALIZABLE_PENALTY_REPAIR` 并停止该修补方向；证据、重复或身份异常仍返回 `DIAGNOSTIC_INVALID`。

证据管线修复阶段已经正式完成，裁决为 `EVIDENCE_SCHEMA_REPAIR_COMPLETE`。冻结 evaluator 输入投影在旧二十四份报告上实现逐指标、逐评价门和逐 margin 精确回放，内存评价与落盘重载评价完全一致；high-lock 比较也已限制为预注册的 high-lock 专属字段。该阶段零次 solver、零次 BO，独立验证与 Standards/Spec 双轴审查均通过，因此其投影、序列化合同、旧回放 fixture 和哈希根可以由后续任务直接继承，无须重做 Stage A。

随后执行的十六次参数—机制责任分界实验仍正式裁决为 `DIAGNOSTIC_INVALID`。执行次数、八个冻结 cell、两遍重复和探索性性能结果均符合计划；探索性结果为四个失败点全部恢复工程通过、四个安全点均不退化。但是 causal episode 使用了错误的 HR_ref 时基与严格不等号：实验 runner 使用逐窗 `ref_hr_bpm` 和 `>10/>20`，而冻结 evaluator 合同要求在 `center_s + 5 s` 上插值并使用 `>=10/>=20`。两个 `fs50` cell 在正确口径下实际存在窗口 236–244 的 E20 episode，首次反事实分叉为窗口 232。实验还存在未穷尽裁决分支、首个 intent 前外部叶依赖哈希不完整，以及独立 validator 未比较 `events`、`high_lock_final_propagation` 和完整规范化语义哈希等证据缺口。最终 code review 未通过，故上述恢复数值只能作为探索性信号，不能升级为正式因果结论或授权生产修改。

若继续该方向，必须使用全新证据根；旧无效根不得原地修补或追溯性转正。新任务先以零 solver 的 TDD 固定正确的 evaluator-aligned causal episode、精确边界、穷尽且 fail-closed 的裁决树、首个 intent 前全部外部叶依赖复哈希，以及覆盖完整语义字段的独立重复比较，并在首个 solver intent 前通过 Standards/Spec 双轴审查。只有此前置门全部通过，才允许原样重做八个 cell、候选删除反事实单 lane、两遍重复的十六次正式计算。

主对话已经授权上述最后一次正式复现。新任务的计划调用数和硬上限均为十六次 solver；Stage A 直接复用且不得重做，BO、其他 cell、其他 lane、观察后扩跑、生产算法修改和默认配置修改均为零。若前置零计算门或预意向双轴审查未通过，任务必须在首次 solver intent 前停止。即使正式结果返回 `PARAMETER_CONDITIONED_EXISTING_MECHANISM_GAP`，本任务也只能形成生产候选的授权依据；非破坏性运动惩罚的实现、四场景非回归和后续放大必须另立任务、重新冻结合同。

全新证据根的正式十六次复现已经完成，唯一裁决为 `PARAMETER_CONDITIONED_EXISTING_MECHANISM_GAP`。Stage A 只读复用，首个科学 intent 前的三十九项 TDD、三百三十七项叶依赖复哈希及 Standards/Spec 双轴审查均通过；正式执行恰为八个 cell、P-only 单 lane、两遍重复的十六次 solver，未运行 baseline、BO、额外记录、额外 cell 或额外 lane。十六份 direct semantic 与同生产 tree 的旧 solver 输出逐份一致，八个 cell 的两遍完整规范化语义逐点一致，独立验证和末次双轴审查均通过，生产 tree 保持不变。

四个 `fs50/fs100, mu=0.008` 失败点均满足“同窗候选硬删除与首次 Final 分叉、分叉早于 aligned E10/E20 和 high-lock”的因果链，并在只保持候选可见的 P-only 反事实中恢复完整工程通过；四个 `fs25, mu=0.008` 或 `fs100, mu=0.006` 安全点的 Final trajectory/hash 精确不变。该结果正式确认候选硬删除是 Run3 开发数据上参数条件化的既有机制缺口，不证明所有参数或所有场景均受影响，也不等于生产修补已经安全。

因此下一步只允许另立最小生产候选与四场景分级非回归任务。候选不得关闭运动惩罚，也不得新增平行恢复器；若继续，应保持 penalty 中心、宽度、权重、置信度、谐波和历史保护不变，只研究候选硬删除与可见性合同。任何生产实现、默认启用、十二折开发验收或 3600 重建仍需后续单独授权和顺序门，不能由本次正式因果裁决自动触发。

主对话已经接受“非破坏性运动惩罚”作为唯一下一生产候选。其领域目标是处理运动伪影频率与真实运动心率频率可能重叠时，硬删除误伤真实候选的风险；所有运行时判断必须来自信号及既有求解状态，不得读取场景、记录、留出误差或 HR_ref 标签。候选只允许保留惩罚带内峰的可见性，同时维持现有 penalty 降权、中心、宽度、权重、置信度、谐波、历史保护及其他机制合同，不得借机增加 Run3 专用分支或新的恢复器。

该方向同时采用时间效率止损原则。Run3 当前主要问题集中于运动段尾端，整体心率结果仍具有较好可用性；因此非破坏性运动惩罚的每一轮研究都必须预注册、有界、分级，不能因一次结果不理想就在同一任务中追加规则、阈值或补丁。首轮冻结为零 solver TDD、十六次 Run3 seam 等价验证及通过后新增二十三次四场景面板；基础累计三十九次，只有按预注册机械风险条件复算时才可增加至五十五次硬上限。首轮结束后必须返回主对话：若结果形成同一机制 seam 上可解释、跨样本同向且未依赖标签的新进展，可以另行授权下一轮有界实验；若只有事后参数特例、跨场景冲突或缺少可生产的信号，则记录并保留已知小缺陷，转向更广泛场景和跨个体验证。

首轮结束后的续研标准冻结为四类。Run3 seam 等价门与四场景面板全部通过时，非破坏性运动惩罚保留为通过有界开发验证的默认关闭候选，但仍不等于生产默认或独立泛化确认。若 Run3 等价门通过而四场景只出现少量、可定位、仍属于同一运动惩罚/候选可见性 seam 的非回归问题，并能提出不依赖场景、记录或 HR_ref 的信号假设，则返回主对话后可以另立下一轮有界诊断。若不能复现 P-only、多个安全样本退化，或继续修正必须依赖场景标签、参数黑名单、揭盲阈值或新增复杂恢复器，则裁定缺乏通用化路径并暂停该路线。若身份、实现等价、确定性或证据管线失败，则只裁定实验无效并修复基础设施，不把它解释为机制方向失败。

首个生产候选 `nondestructive_weighted_visible_v1` 的三十九次有界执行正式裁决为 `EXPERIMENT_INVALID`：inactive FFT window 的默认 trace 身份与独立 validator 要求的逐窗候选字段不一致，风险投影又把纯候选元数据变化计为二十三个风险 cell，超过十六个复算上限。该身份不得追加或追溯性转正，候选继续默认关闭；现有 raw reports 只允许用于零 solver 诊断。

零 solver 诊断同时反证了“全部惩罚带峰立即可选”的目标语义。`kaihe1_LYX_0617` 在窗口六十把本应删除的约 65.19 BPM 运动峰恢复为主候选，其加权幅值仍高于约 87.16 BPM 上升候选，导致原本在窗口六十至六十八建立并重锚的 intended-rise 谱系消失，MAE 从约 3.25 增至 36.89 BPM；`kaihe1_LYX_0613` 在窗口六十九同样重新采纳约 115.72 BPM 的运动倍频，MAE 从约 2.97 增至 6.12 BPM。两处首次 tracked 分叉时 penalty 中心、宽度、权重、置信度、谐波和 Final writer 均未改变，因此问题属于无条件主选择资格，而不是 rise、高锁、评价器或 penalty 观测变化。

后续非破坏性研究收窄为现有历史保护的职责修补。四个 Run3 失败层级在首次有效反事实窗口都存在同一无标签事件：上一轨迹的受保护目标位于既有 3.5 BPM 保护走廊内，但保护因 challenger 成立而被压制；四个 Run3 安全层级和两个 Kaihe 首次退化窗口均不存在该事件。因此只允许研究“受压保护目标影子所有权”：压制当窗仍采用 challenger，原保护目标最多在随后三个运动窗口内按既有保护走廊匹配并作为唯一可释放的惩罚带候选；它不强制选择、不写 Final，并在目标缺失、漂移失配、自然离开惩罚带、到期、运动结束或 EOF 时终止。普通 would-remove 峰、运动主频和倍频不得取得该所有权。

主对话已授权把证据设施修复、默认关闭的 `suppressed_protected_shadow_v1` 候选和有界验证放在一个独立任务中按顺序门执行。第一门零 solver 修复 inactive-window 的按路径 trace 验证与风险投影，并用旧三十九份 raw reports 证明 validator 能同时保留 Run3 seam 等价证据并识别两个 Kaihe 真实退化。第二门运行十二个核心 cell各两遍：Run3 四红四安全、两个 Kaihe 已知退化点、一个 Kaihe 安全点及一个实际出现同类保护压制的 Jianpan 安全点，共二十四次；只有该门通过才补跑既有三十一 cell 四场景面板中剩余十九个 cell。随后只允许对机械生成的真实语义风险集复算，最多十二次，基础四十三次、科学调用硬上限五十五次；风险集超过十二个时返回主对话，不得截断或自动扩大。

候选必须使四个 Run3 红点全部恢复工程通过，并保持四个 Run3 安全点、三个 Kaihe 哨兵和其他既有通过结果不丢失；`kaihe1_LYX_0617` 的 intended-rise 序列不得改变。任何 Kaihe 退化、Run3 救援不全、新增评价门、所有权未闭合、新 Final writer、身份/确定性/验证失败都立即停止。任务不得运行 BO、增加记录、重建 3600、修改冻结评价合同或默认启用候选；即使全部通过，也只能称为受压保护目标修补通过有界开发验证，Run1 未解决时不得声称固定选择器十二折完成。

`suppressed_protected_shadow_v1` 的首轮核心实验已在二十四次 solver 后按门停止，唯一正式裁决为 `EXPERIMENT_INVALID`。执行范围、两遍确定性、owner 生命周期和单一 Final writer 的局部检查可复算，但独立验证器没有重建冻结 evaluator 的完整规范输入包，并直接比较跨 JSON 边界的 tuple 与 list，造成伪 G1-I 与 trace mismatch；最终 Standards/Spec 双轴审查均失败。因此该证据根不得续跑、修补后转正或用来声明候选科学成功/失败，Gate C、风险复算、BO 和 3600 均未执行。

主对话据此同意继续一次有界的“受压保护目标同窗证据可见性”研究，不原样复算 `suppressed_protected_shadow_v1`。新方向只允许在既有 challenger 压制发生的同一窗口，把原受保护目标保留在下游候选证据池；challenger 仍是当窗前置选择，不强制采用目标、不写 Final，也不建立跨窗 owner。任何新计算前必须先以零 solver 修复 evaluator 规范输入重放与 JSON 结构规范化，并建立全新的实验身份；若同窗方向仍不能救回 Run3 或造成 Kaihe/Jianpan 退化，则快速收尾并转向更广场景与跨个体研究。

下一轮采用一个独立任务内的顺序门。门 A 以零次 solver 建立 evaluator 规范输入的唯一构造入口，并在跨 JSON 边界前规范化 trace audit；旧二十四份 shadow raw reports只作为红绿 fixture，旧正式裁决保持无效。门 B 只运行一个无跨窗状态的同窗可见性 lane，在既有十二个核心 cell 上各重复两遍，共二十四次；四个 Run3 红点必须全部恢复工程通过，四个 Run3 安全点和三个 Kaihe 哨兵必须保持冻结结果，Jianpan 压制反例不得退门，两遍科学语义必须逐点一致。门 B 任一失败即返回，不运行其他 cell，也不在任务内增加第二个机制。

该同窗实验已经按门完成，唯一正式裁决为 `NO_GENERALIZABLE_SUPPRESSED_PROTECTED_SAME_WINDOW_PATH`。门 A 的 evaluator 规范输入与 JSON 规范化修复通过；门 B 完成十二个核心 cell 各两遍，共二十四次 solver，十二组两遍完整语义一致，独立验证与最终 Standards/Spec 双轴审查均通过。四个 Run3 红点在冻结因果窗口均精确加入原受压保护目标，同时保持 challenger 身份不变，但四点的 `post_active_final_changed` 均为 false，Final、指标和评价门仍与失败基线一致；因此按合同停止，门 C、风险复算、BO 和 3600 调用均为零。四个 Run3 安全点和三个 Kaihe 哨兵的 Final、指标与评价门保持不变，但不得外推为完整角色语义等价。

零 solver 对比进一步解释了该负结果：P-only 全量可见反事实并不是在压制同窗立即改写前置选择，而是在随后的连续窗口中持续保留约 120–127 BPM 候选，才让既有选择、限速和居中平滑链逐步回到正确轨迹。原影子候选只在下一窗释放一次，随后重新硬删除；同窗候选又只在 challenger 已胜出的当前窗存在，两者都没有覆盖这段连续证据需求。该观察只能提出“受压保护目标跨连续窗口保持可见”的新假设，不能授权强制选择、Final 写入或按固定窗口数直接生产化。若继续研究，必须先通过主对话的时间效率止损裁决，并另立实验身份；若停止，则保留 Run3 已知小缺陷并转向更广场景与跨个体研究。

主对话已经通过该时间效率止损裁决，授权下一轮默认关闭的 `suppressed_protected_continuous_visibility_v1` 有界实验。候选沿用既有受压保护目标身份、保护走廊和最多三个后续运动 invocation 的期限；压制当窗仍保留 challenger，随后只要同一目标仍匹配、仍处于惩罚带并且运动作用域有效，就在每个窗口持续进入既有加权候选集合。首次匹配不得终止 owner，选择仍由现有选择器完成；目标缺失、漂移失配、自然离开惩罚带、期限耗尽、运动结束、recovery/rest 或 EOF 必须显式 release/terminal。候选不得读取场景、记录、参数坐标、HR_ref 或评价门，不得强制选峰、增加 Final writer、改变 penalty 中心/宽度/权重/置信度/谐波或修改 rise、reacquire、low/high-lock 合同。
