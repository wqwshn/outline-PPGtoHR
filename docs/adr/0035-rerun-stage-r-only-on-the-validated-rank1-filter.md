# ADR 0035：仅在已验证的 Rank-1 滤波结构上修复性续跑 Stage R

状态：Accepted  
日期：2026-07-30

## 背景

原 Stage R 在三个滤波哨兵和三个恢复候选上运行了 108 个正式身份，但所有候选均被淘汰。后续证据表明，淘汰结果混入了候选无关的滤波频谱失败。机制分解进一步定位到双级 HF 自适应级联的第二次串行更新；`p25-short-low-rank1-v1` 已在 12 条 LYX 开发记录上完成 12/12 频谱安全和逐值复现。

旧三个哨兵在修正后的频谱量纲与脉搏功率保留硬门下均不适合作为新的正式入口。继续运行它们会重复已知失败，无法回答恢复机制优劣。

## 决策

Stage R 采用修复性续跑：

- 保留旧 60 个阈值诊断和旧 108 个正式身份为历史证据；
- 不把旧结果与新结果拼接为同一选择面板；
- 只新增 3 个冻结恢复候选 × 1 个 `p25-short-low-rank1-v1` × 12 条记录，共 36 个 formal 身份；
- 滤波固定、恢复变化、惩罚固定为当前控制，从而隔离恢复机制；
- 使用单滤波结构版本的恢复选择合同，保留原九项硬门和字典序排序；
- 无安全候选时停止到完整独立 BO 人工审核，不自动运行 BO；
- 有安全候选时只进入新版 Stage F 的人工重规划门，不自动运行 Stage F。

## 理由

一个滤波结构不足以证明恢复机制对任意滤波组合都稳健，但当前实验问题已经从“选择多个滤波哨兵”转为“验证唯一通过机制修订的滤波实现是否能支撑统一恢复机制”。在已知不安全的旧哨兵上增加 108 次求解不会提高判别力。36 身份是能完成当前恢复比较的最小完整矩阵。

## 后果

- 本阶段可选择 LYX 暂定恢复机制，但不能宣称跨场景或跨个体泛化；
- 若未来出现第二个频谱安全滤波结构，需要新提案扩充恢复鲁棒性验证；
- 原 Stage R 选择合同保持不变，新合同是显式续跑版本；
- v11 治理预算比 v10 增加 36 个 formal 身份，最坏尝试上限增加 72；
- 独立 BO lite 仍是主要性能比较基线，`TraceRescue` 仅保留历史探索角色。
