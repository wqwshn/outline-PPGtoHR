## What to build

从冻结真实结果完成论文级图件、研究报告、语言润色和最终验收。沿用项目 Python 科研绘图链，每张图先建立核心结论、证据链、面板职责、导出格式和审稿风险，再生成 600 dpi 审阅 PNG 与正式矢量/栅格交付。报告按“收益—边界—失败机制—下一轮接口问题”组织，所有主张映射到真实表、图或失败证据。

随后以研究分支基准为固定点执行 Standards 与 Spec 双轴代码审查，修复发现并复审；最后逐项核对父 PRD、spec 和六个子 Issue 的测试、门槛、工件与结论，不以测试通过替代完整范围审计。

## Acceptance criteria

- [ ] 每张正式图均保存 figure contract，说明核心结论、独有证据、图型、尺寸、统计、源数据、导出格式和审稿风险。
- [ ] 至少交付全记录频谱配对图、场景×折次热图、频谱—MAE 四象限图、正反例时频图、通道/子带贡献图、场景条件化与统一参数对照图及 BO 上限差距图。
- [ ] 迭代图输出 600 dpi PNG；正式交付按 contract 输出可编辑 SVG/PDF 及所需高分辨率栅格，并完成视觉 QA。
- [ ] 图中参考、主算法、次算法、baseline 和事件背景遵循项目固定层级，单位、样本量、误差定义和统计单位完整。
- [ ] 报告先按 Nature 证据逻辑重建，再做语言润色；不得虚构数据、统计、机制、引用或跨人结论。
- [ ] 每个主要结论均有 claim–evidence–boundary 映射，明确 CGX 单个体、开发反馈污染和 Stage B 只诊断的边界。
- [ ] 相关窄测试、完整 Python 测试、所有 manifest/verifier 与图件解码检查均通过。
- [ ] 代码审查以明确基准运行 Standards 与 Spec 两个独立轴，完整报告并修复所有阻断性发现后复审。
- [ ] 最终完成审计逐项证明父 PRD、spec 和 #35–#39 的命名产物、门槛、不变量与停止条件均已满足。
- [ ] 研究报告、图件、配置、源数据、审查结果和最终审计均提交到研究分支，工作树洁净。
