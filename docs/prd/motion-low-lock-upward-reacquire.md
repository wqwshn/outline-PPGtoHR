# 运动段低锁上跳重捕获优化 PRD

## Problem Statement

当前 v2 心率算法中的“低频重捕获”实际是运动段低锁上跳重捕获：当 adaptive 谱峰追踪状态连续落在 50-80 BPM 等偏低区域时，机制尝试跳向较高候选峰，以修复开合跳、波比等场景中真实心率上升但轨迹锁在运动低频伪峰的问题。

历史回放证明该机制曾在 `multi_kaihe1`、`multi_kaihe2`、`multi_bobi3` 等样本上带来明显收益，运动段 MAE、P90 误差和最长连续失败段均有改善。但 2026-07-08 LYX 腕部细小持续运动实验显示，同一机制在写字、敲键盘、握力计等真实心率变化不大的场景中严重误触发，把原本可达的真实心率峰推成 `visible_not_in_range`，并使输出跳到约 180-220 BPM 的疑似运动伪峰或谐波区域。

因此，问题不是简单决定“保留或删除低频重捕获”，而是需要把它重设计为一个基于相对证据门控的运动段低锁上跳机制：既保留历史救援收益，又避免在写字、键盘、握力计等场景中破坏真实峰可达性。

## Solution

重设计运动段低锁上跳重捕获，使其从固定阈值状态机转为相对证据门控的追踪状态恢复机制。新机制应先判断是否存在真实上升证据，再通过候选资格过滤排除明显不安全的上跳目标，通过候选相对评分选择最可信的上升候选，触发后优先执行可达性修复，而不是直接改写 Final HR。

机制在线触发不得使用参考心率、离线误差、Lite/KLMS 对照结果或 ACC 对比参考信号作为 HF 主链路决策证据。ACC 可继续作为运动段划分依据，并作为 HF 消除运动伪影能力的公平对照链路；ACC 链路应获得同样机制，但不改变本轮主目标：优化低锁上跳机制本身。

实验应使用三组样本矩阵完成闭环：

- 历史救援组：验证开合跳、波比等低锁上跳收益不能丢。
- 当前防误伤组：验证写字、敲键盘、握力计中不再大量误触发，拳击作为弱负对照。
- 历史高频锁定组：验证低锁上跳优化不污染高频锁定逃逸场景。

验收采用低锁上跳三层验收：先看防误触发，再看历史救援保留，最后再比较总体 MAE、hit rate、range reachable 和触发统计。

## User Stories

1. As an 算法研究者, I want 明确区分运动段低锁上跳重捕获和泛化的低频重捕获, so that 我能针对真实机制设计触发和退出条件。
2. As an 算法研究者, I want 保留开合跳、波比等历史救援样本的低锁修复能力, so that 优化不会退化为简单禁用机制。
3. As an 算法研究者, I want 写字、敲键盘和握力计样本不再因低锁上跳产生大量 `visible_not_in_range`, so that 真实心率变化不大的细小运动场景不会被误伤。
4. As an 算法研究者, I want 触发条件基于真实上升证据, so that 机制只在窗口序列支持心率上升时介入。
5. As an 算法研究者, I want 机制少依赖绝对 BPM 门槛, so that 同一套规则在不同被试、场景和心率水平下更容易泛化。
6. As an 算法研究者, I want 先做候选资格过滤, so that 单窗冒尖、运动伪峰和谐波候选不会直接成为上跳目标。
7. As an 算法研究者, I want 再做候选相对评分, so that 多个合格上升候选能按稳定性、幅值竞争和轨迹一致性排序。
8. As an 算法研究者, I want 触发后优先修复可达性, so that 机制先扩展或迁移搜索范围，而不是直接把 Final HR 硬切到候选峰。
9. As an 算法研究者, I want 上跳候选进入可达范围后仍由正常候选选择确认, so that 远端伪峰不能靠一次触发长期污染轨迹。
10. As an 算法研究者, I want 机制具备失败快速退出, so that 在线误判不会把后续窗口持续带偏。
11. As an 算法研究者, I want 退出后不进入过长冷却, so that 真正的开合跳低锁仍能在后续窗口被救援。
12. As an 算法研究者, I want 每个窗口记录低锁上跳状态、候选、过滤原因、评分证据和退出原因, so that 后续能用窗口失效原因分类复盘机制行为。
13. As an 算法研究者, I want HF 主链路不使用 ACC 作为触发证据, so that 机制优化不会混入参考源变化。
14. As an 算法研究者, I want ACC 链路获得同样机制并作为对比读数, so that HF 与 ACC 的参考信号对比保持公平。
15. As an 算法研究者, I want 低锁上跳机制适用于所有 v2 算法预设, so that Lite、TraceRescue 和其他共享 solver 路线不会出现分叉语义。
16. As an 算法研究者, I want KLMS 生产默认门控语义保持谨慎, so that 不会因为实验 allowlist 结果而无意改变 KLMS 默认行为。
17. As an 算法研究者, I want 高频锁定逃逸和低锁上跳分开评估, so that 两个相反方向的恢复机制不会互相掩盖收益或副作用。
18. As an 算法研究者, I want 实验报告固定展示真实峰可见性、真实峰可达性和机制门控效应, so that 输出误差不会被误读为频谱证据质量。
19. As an 算法研究者, I want 报告列出 `visible_not_in_range`、`in_range_not_selected`、`selected_but_limited_away` 等窗口失败主因, so that 可以判断机制到底修复了可达性还是制造了不可达性。
20. As an 算法研究者, I want 代表窗口图展示 previous HR、search range、candidate peaks、penalty centers 和 final HR, so that 可以直接观察机制是否把轨迹推离真实峰。
21. As an 算法研究者, I want 历史救援组和当前防误伤组在同一报告中并列, so that 参数或规则不会只对单一场景过拟合。
22. As an 算法研究者, I want 实验仍采用 Lite + HF 主参考 + ACC 对比参考信号, so that 本轮结果聚焦低锁上跳机制优化。
23. As an 算法研究者, I want 不新增大量 BO 参数来掩盖机制问题, so that 机制行为保持可解释和可复盘。
24. As an 算法研究者, I want 可以基于现有窗口 trace 做离线 replay, so that 候选门控和评分策略能先快速验证再进入 solver。
25. As an 算法研究者, I want 最终实现通过 solver 公共行为测试验证, so that 测试覆盖真实外部行为而不是私有函数细节。

## Implementation Decisions

- 新机制的规范名称是运动段低锁上跳重捕获，不再把它泛称为低频重捕获。
- 机制目标是修复运动段低锁状态下较高真实候选峰不可达的问题，不是提供任意远端候选跳转。
- 触发结构采用相对证据门控：低锁状态只是必要背景，不能单独触发上跳。
- 真实上升证据来自在线可用信号，包括候选峰跨窗口稳定性、候选幅值竞争、历史轨迹一致性、运动阶段动态和当前参考链路自身的谱峰/惩罚关系。
- 在线触发不得使用参考心率、离线误差、Lite/KLMS 对照曲线或任何答案派生信号。
- HF 主链路不得使用 ACC 作为触发、候选选择或评分证据；ACC 只作为运动段划分依据和对比参考链路。
- ACC 链路应复用同一套低锁上跳机制，以保证参考信号对比公平，但本轮主结论仍围绕机制优化。
- 候选选择分两层：候选资格过滤先排除不安全目标，候选相对评分再排序合格候选。
- 候选资格过滤应覆盖单窗冒尖、候选靠近运动伪峰或谐波、候选会破坏合理心率区域可达性、候选与窗口序列证据严重冲突等情况。
- 候选确认不得要求已经低锁的输出先自行向候选上升；该条件会形成“恢复前必须已经恢复”的循环依赖。输出轨迹用于界定低锁背景和修复走廊，不作为候选存在的替代证据。
- 三窗确认采用非循环的双证据择一：候选峰自身累计漂移不低于 -1 BPM 时可独立确认；若候选峰明显回落，则仅在低锁轨迹同时呈现足够上升漂移时确认。后一条是回落候选的旁证通道，不是所有真实上升候选的前置条件。
- 候选确认后应冻结目标并改用持续支持判据，不得因轨迹已接近目标、入场跳差自然缩小而误判候选丢失；目标附近支持消失时才快速退出。
- 第一版资格过滤采用少量、全样本共享的物理边界：连续 4 窗位于 50-80 BPM；候选至少 90 BPM、相对当前轨迹至少上升 20 BPM；候选幅值至少达到原始谱最强峰的 50%；候选与主运动惩罚中心及其谐波至少相隔 10 BPM；候选最多超出普通上行搜索范围 5 BPM；连续 3 窗稳定，且满足候选峰累计漂移不低于 -1 BPM或低锁轨迹上升漂移至少达到上行步长的 75% 与候选距离的 12% 两者较大值，才触发。
- 候选相对评分应比较跨窗口稳定性、幅值竞争、与 previous HR 的相对关系、与惩罚中心或伪峰的关系、以及触发后搜索范围是否仍保持合理可达。
- 触发后的主要动作是可达性修复：调整搜索范围、追踪中心或候选可采纳性，让合理上升候选进入可达区域。
- 机制不应直接把 Final HR 改写为候选峰；候选进入可达范围后仍需接受正常谱峰选择和后处理约束。
- 机制必须包含失败快速退出：候选连续失稳、上跳后不再合格、搜索范围持续远离合理区域、或输出被推向疑似谐波/运动伪峰区时，应退出回普通追踪。
- 退出后的冷却应足够短，避免真正低锁救援窗口被长期屏蔽。
- 高频锁定逃逸继续作为独立机制评估，不与低锁上跳合并成一个门控开关。
- KLMS 机制门控仍应通过实验 allowlist 显式启用；生产默认语义不因本轮实验自动改变。
- 诊断 payload 应记录机制有效状态、低锁状态、真实上升证据、候选过滤结果、候选评分摘要、可达性修复动作、退出原因和触发统计。
- 实验 runner 应支持历史救援组、当前防误伤组和历史高频锁定组的统一运行与汇总。
- 报告应把防误触发、历史救援和总体指标按低锁上跳三层验收顺序呈现。

## Testing Decisions

- 测试优先覆盖 v2 solver 公共行为和实验报告输出，不围绕私有辅助函数建立脆弱断言。
- solver 层测试应验证低锁状态下，只有存在真实上升证据和合格候选时才触发可达性修复。
- solver 层测试应分别覆盖候选峰趋势独立通过、回落候选由低锁轨迹上升旁证通过，以及两条证据均失败时拒绝三个公共行为。
- solver 层测试应验证单窗高峰、疑似谐波或运动伪峰候选不会直接触发上跳。
- solver 层测试应验证触发后不会直接硬改 Final HR，而是通过搜索范围或候选可达性影响后续选择。
- solver 层测试应验证候选失稳或修复失败时会快速退出，并且不会长时间保持错误状态。
- solver 层测试应验证轨迹接近仍受支持的冻结目标时正确完成恢复，而不是复用入场跳差并误报候选丢失。
- solver 层测试应验证 KLMS 默认生产语义不启用机制门控，实验 allowlist 才能打开。
- replay 或分析层测试应验证窗口级诊断字段足以区分 `visible_not_in_range`、候选不合格、评分未通过、可达性修复和失败退出。
- 实验脚本测试应验证三组样本矩阵可以被稳定枚举，并能分别输出历史救援组、当前防误伤组和历史高频锁定组指标。
- 报告测试应验证低锁上跳三层验收顺序固定呈现，避免只用总体 MAE 作为主结论。
- 回归验证应至少运行相关 solver 测试、低锁上跳实验脚本测试、窗口分析测试和报告生成测试。
- 最终实验验证应使用 conda 环境 `ppg-hr`，并保持 `PYTHONPATH` 指向当前 worktree 的 `python/src`。
- 机制回归必须使用每条记录独立进程的开关配对回放，避免运行态相互污染；历史救援组、当前防误伤组和历史高频锁定组分别汇总，开发复用数据不得表述为留出或迁移验证。
- 正式配对回放必须绑定完整算法源码树与每条原始/参考输入哈希；缓存复用和结果聚合都应重新核验绑定，发现漂移时默认失败关闭。
- 若修改没有新增 BO 参数，且固定配置配对回放已经覆盖正例、负例和相邻机制，默认不以完整独立 BO 代替机制因果检验；只有固定配置证据无法区分机制与参数空间影响时，才补充代表样本独立 BO。

## Out of Scope

- 本 PRD 不要求重设计高频锁定逃逸机制。
- 本 PRD 不要求评估 HF 相比 ACC 的抗伪影能力作为主研究问题。
- 本 PRD 不把 ACC 引入 HF 主链路的触发或候选选择。
- 本 PRD 不要求改变运动后动态保护窗、运动后静息 FFT 重捕获或 post-motion 回切机制。
- 本 PRD 不要求新增大量 BO 搜索参数。
- 本 PRD 不承诺解决真实心率峰完全不可见的运动段失效。
- 本 PRD 不要求将 KLMS 加入生产默认机制门控。
- 本 PRD 不要求在第一版引入复杂 PPG 质量模型或训练式分类器。
